# Phase 8: AI, transcription and auto-sort

**Goal:** voice memos get transcripts, and captured scraps get "file under..." suggestions the user accepts or dismisses. Nothing moves on its own.

**Depends on:** Phase 7, and the owner's choice of transcription provider (DECISIONS open question 2). **Read:** SPEC 9.4 (transcription), 9.5, 6.7 (AI section), 12.

## Tasks

- [x] **8.1 Provider interface.** `TranscriptionProvider { transcribe(audio: Blob, mime: string, languageHint?: string): Promise<{ text: string; language?: string }> }` with the chosen provider and a `FakeProvider` for tests. Provider picked by `TRANSCRIPTION_PROVIDER` env.
- [x] **8.2 `transcribe-audio` function.** Database webhook on audio `assets` insert sets status `pending`, downloads the file with the service role, calls the provider, writes `transcript` and `done` or `failed`. Retries twice with backoff. Writes the transcript to `assets`; the `assets` trigger maintains `notes.transcript_tsv` (never touch `search_text`). Includes a one-off backfill for audio assets created in Phases 4 to 7 (status `none`).
- [x] **8.3 Transcript UI.** Voice block shows "transcribing…", then the transcript (collapsible), a "copy into note" action and "retry" on failure; card shows the excerpt in the mono speech box. Updates arrive through Realtime on the asset row.
- [x] **8.4 `ai-sort` function.** Builds the input from SPEC 9.5 only, calls Claude `claude-haiku-5-5` with a system prompt that treats note text as data and requires JSON output; validates with zod; stores in `ai_suggestions`; skips under confidence 0.5; rate limit 60/hour per user; honours `profiles.ai_enabled` (default false; add the one-time opt-in prompt on first capture).
- [x] **8.5 Suggestion toast.** After capture (sheet, share target, shortcut), show "file under **space**? add #tag #tag" with "yes" and "nah"; "yes" moves the note, adds or creates tags and sets the title if the scrap had none; "nah" dismisses. Also "suggest where this goes" in the note menu.
- [x] **8.6 Settings and notice.** AI toggle with a one-line explanation of what is sent; first-use notice inside the first suggestion toast ("ai looked at the text of this scrap to suggest this. change it in settings").
- [x] **8.7 Evals.** A small fixture set (30 scraps across the seed spaces) with expected spaces; script that runs `ai-sort` against them and reports accuracy, so prompt changes can be checked. Keep under `supabase/functions/ai-sort/evals`.

## Acceptance criteria
- [ ] Recording a 20-second memo produces a transcript in the block within 30 seconds; search finds a word from it. _(Verified end to end with the fake provider and a 2.5 second memo in `e2e/ai.spec.ts`. Needs a Groq key to tick for real.)_
- [ ] Capturing "book train tickets for goa trip" in brain dump suggests "side quests" with a travel tag on the seed data; accepting moves it. _(Accepting moves and tags it, verified with a mocked function answer. The model's own answer needs an Anthropic key: run `pnpm evals:ai-sort`.)_
- [x] With AI turned off, no `ai-sort` calls are made (verify in function logs). _(No call leaves the browser, and the function answers 403 `ai_disabled` before any model call; both tested.)_
- [x] Malformed model output never errors the UI; it simply shows no suggestion.

## Tests (minimum)
- Unit: input builder (field caps, no extra data), output validation, rate limiter.
- Integration: transcription with `FakeProvider`; ai-sort with a mocked Claude client.
- E2E: capture flow shows and accepts a suggestion (mocked function response).

## Out of scope
AI writing, summaries, image understanding, alt-text generation.
